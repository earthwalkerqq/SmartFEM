# Процесс генерации сетки и расчета количества элементов

## Общая схема процесса

```
Пользователь задает желаемое количество элементов
         ↓
GUI: calculateMeshParams() - расчет clmin и clmax
         ↓
GUI: generateMesh() - запуск bash скрипта
         ↓
generate_mesh.sh - вызов Gmsh CLI
         ↓
Gmsh генерирует .msh файл с сеткой
         ↓
convert_msh.py - конвертация .msh → node.txt
         ↓
generate_adjacency.py - генерация файла смежности
         ↓
Готовая сетка в node.txt для FEM модуля
```

## Детальное описание этапов

### 1. Расчет параметров сетки (GUI: `calculateMeshParams()`)

**Входные данные:**
- Желаемое количество элементов (пользователь задает)
- Площадь модели (из существующей сетки или значение по умолчанию: 520.0)

**Формула расчета:**
```cpp
// Базовый расчет
elementAreaFactor = 0.433  // Коэффициент для треугольных элементов
baseClmax = sqrt(estimatedArea / (elementAreaFactor * desiredElements))

// Корректирующий коэффициент (зависит от desiredElements)
if (desiredElements < 50):
    correctionFactor = 1.0 + 0.8 * log(50.0 / (desiredElements + 1.0))
    correctionFactor = ограничить от 1.5 до 3.0
else if (desiredElements < 200):
    correctionFactor = 1.0 + 0.4 * log(200.0 / (desiredElements + 1.0))
    correctionFactor = ограничить от 1.2 до 1.8
else if (desiredElements < 1000):
    correctionFactor = 1.0 + 0.2 * log(1000.0 / (desiredElements + 1.0))
    correctionFactor = ограничить от 1.1 до 1.4
else:
    correctionFactor = 1.1

// Финальный clmax
clmax = baseClmax * correctionFactor

// Расчет clmin
if (desiredElements < 50):
    clminRatio = 0.75  // clmin = 75% от clmax
else if (desiredElements < 200):
    clminRatio = 0.6   // clmin = 60% от clmax
else if (desiredElements < 1000):
    clminRatio = 0.4   // clmin = 40% от clmax
else:
    clminRatio = 0.25  // clmin = 25% от clmax

clmin = clmax * clminRatio
```

**Почему нужна корректировка:**
- Gmsh генерирует больше элементов, чем предсказывает простая формула
- Особенно для малого количества элементов из-за адаптации к геометрии
- Логарифмическая функция обеспечивает плавный переход между диапазонами

### 2. Генерация сетки через Gmsh (`generate_mesh.sh`)

**Команда Gmsh:**
```bash
gmsh -2 "${STEP_FILE}" -clmin "${CLMIN}" -clmax "${CLMAX}" -format msh2 -o "${OUTPUT_MSH}"
```

**Параметры:**
- `-2`: 2D сетка (треугольные элементы)
- `-clmin`: Минимальный размер элемента
- `-clmax`: Максимальный размер элемента
- `-format msh2`: Формат MSH версии 2
- `-o`: Выходной файл

**Как Gmsh генерирует элементы:**
1. Gmsh анализирует геометрию из STEP файла
2. Применяет адаптивную сетку с учетом `clmin` и `clmax`
3. Генерирует треугольные элементы (тип 2 в формате MSH)
4. Сохраняет узлы и элементы в `.msh` файл

**Важно:** Gmsh не гарантирует точное количество элементов, так как:
- Адаптируется к геометрии (более мелкая сетка в сложных областях)
- Учитывает границы и особенности формы
- Может генерировать больше элементов для лучшего качества сетки

### 3. Конвертация .msh → node.txt (`convert_msh.py`)

**Что делает скрипт:**
1. Читает секцию `$Nodes` из .msh файла
   - Извлекает координаты всех узлов
   - Сохраняет в формате: `номер_узла x y z`

2. Читает секцию `$Elements` из .msh файла
   - Фильтрует только треугольные элементы (тип 2)
   - Извлекает номера узлов для каждого элемента
   - Сохраняет в формате: `узел1 узел2 узел3`

3. Автоматически определяет граничные условия
   - Узлы на левой грани (x_min) → закрепление по U (x)
   - Узлы на нижней грани (y_min) → закрепление по V (y)
   - Использует допуск 5% от размера модели

4. Записывает в `node.txt`:
   ```
   количество_узлов
   x1 y1 z1 u_flag1 v_flag1 load_flag1
   x2 y2 z2 u_flag2 v_flag2 load_flag2
   ...
   количество_элементов
   узел1_элемент1 узел2_элемент1 узел3_элемент1
   узел1_элемент2 узел2_элемент2 узел3_элемент2
   ...
   ```

**Количество элементов определяется:**
- Из секции `$Elements` в .msh файле
- Подсчитываются только треугольные элементы (тип 2)
- Записывается в `node.txt` после списка узлов

### 4. Генерация файла смежности (`generate_adjacency.py`)

**Что делает скрипт:**
1. Читает узлы и элементы из .msh файла
2. Создает словарь смежности: для каждого узла находит все элементы, которым он принадлежит
3. Записывает в `adjacency.txt`:
   ```
   количество_узлов
   номер_узла1 x1 y1 z1 количество_смежных_элементов элемент1 элемент2 элемент3
   номер_узла2 x2 y2 z2 количество_смежных_элементов элемент1 элемент2 элемент3
   ...
   количество_элементов
   узел1_элемент1 узел2_элемент1 узел3_элемент1
   ...
   ```

## Почему реальное количество элементов может отличаться от желаемого?

### Причины:

1. **Адаптивная сетка Gmsh:**
   - Gmsh автоматически уменьшает размер элементов в сложных областях
   - Увеличивает плотность сетки на границах и в углах
   - Это улучшает качество сетки, но увеличивает количество элементов

2. **Геометрия модели:**
   - Сложная геометрия требует больше элементов для аппроксимации
   - Изогнутые границы генерируют больше элементов
   - Мелкие детали требуют более мелкой сетки

3. **Ограничения clmin и clmax:**
   - Gmsh не может создать элементы меньше `clmin`
   - Не может создать элементы больше `clmax`
   - Между этими значениями адаптируется к геометрии

4. **Формула расчета:**
   - Формула `элементы ≈ площадь / (0.433 * clmax²)` является приближенной
   - Она основана на предположении о равномерной сетке
   - Реальная сетка почти никогда не бывает равномерной

### Решение проблемы:

1. **Корректирующий коэффициент:**
   - Увеличивает `clmax` для малого количества элементов
   - Компенсирует тенденцию Gmsh генерировать больше элементов

2. **Автоматическая корректировка:**
   - После генерации сетки проверяется реальное количество элементов
   - Если отличается более чем в 2 раза, предлагается автоматическая корректировка `clmax`
   - Пользователь может принять или отклонить корректировку

3. **Ручная корректировка:**
   - Пользователь может вручную изменить `clmax` в GUI
   - Повторно сгенерировать сетку с новыми параметрами

## Формулы и коэффициенты

### Коэффициент 0.433:
```
Площадь равностороннего треугольника = (sqrt(3) / 4) * h²
где h - характерная длина элемента (clmax)

Для треугольной сетки:
количество_элементов ≈ площадь_модели / площадь_одного_элемента
количество_элементов ≈ площадь / ((sqrt(3) / 4) * clmax²)
количество_элементов ≈ площадь / (0.433 * clmax²)

Отсюда:
clmax² = площадь / (0.433 * количество_элементов)
clmax = sqrt(площадь / (0.433 * количество_элементов))
```

### Корректирующий коэффициент:
```
Для малого количества элементов (< 50):
correctionFactor = 1.0 + 0.8 * log(50.0 / (desiredElements + 1.0))
Ограничен от 1.5 до 3.0

Для среднего количества элементов (50-200):
correctionFactor = 1.0 + 0.4 * log(200.0 / (desiredElements + 1.0))
Ограничен от 1.2 до 1.8

Для большого количества элементов (200-1000):
correctionFactor = 1.0 + 0.2 * log(1000.0 / (desiredElements + 1.0))
Ограничен от 1.1 до 1.4

Для очень большого количества элементов (> 1000):
correctionFactor = 1.1
```

## Файлы и форматы

### Входные файлы:
- `*.stp` или `*.step` - CAD модель в формате STEP

### Промежуточные файлы:
- `HyperMesh.msh` - сетка в формате Gmsh MSH2

### Выходные файлы:
- `node.txt` - сетка в формате для FEM модуля:
  ```
  количество_узлов
  x1 y1 z1 u_flag1 v_flag1 load_flag1
  x2 y2 z2 u_flag2 v_flag2 load_flag2
  ...
  количество_элементов
  узел1_элемент1 узел2_элемент1 узел3_элемент1
  ...
  ```

- `adjacency.txt` - файл смежности (опционально)

- `loads.txt` - нагрузки на узлы:
  ```
  номер_узла Fx Fy
  ...
  ```

## Рекомендации

1. **Для точного контроля количества элементов:**
   - Используйте автоматическую корректировку после первой генерации
   - Или вручную скорректируйте `clmax` на основе реального количества элементов

2. **Для лучшего качества сетки:**
   - Не задавайте слишком мало элементов для сложной геометрии
   - Используйте соотношение `clmin / clmax` от 0.4 до 0.75 для равномерной сетки

3. **Для быстрой генерации:**
   - Используйте большее значение `clmax` для грубой сетки
   - Уменьшайте `clmin` только если нужно более детальное разрешение в определенных областях
